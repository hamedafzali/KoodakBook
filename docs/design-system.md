# KoodakBook Design System — «نارنج»

> **This document describes what is built, after the `design-recovery` pass
> (2026-09).** [`/DESIGN_CHARTER.md`](../DESIGN_CHARTER.md) is the source of
> truth for intent; this is the implementation reference. Where they ever
> disagree, the charter wins and this file is wrong and should be fixed.

**The one-line version:** this is a children's app, and colour, illustration,
gradient, rounded type and emoji are the *product*. The system exists to make
that joy consistent and accessible — not to sand it down. Every contrast floor
below is met by pairing **dark ink on a bright fill**, never by draining the
fill toward grey.

**Scope:** both registers of `apps/web` — the child surfaces (clay) and the
parent surfaces (flat, all eight screens). Admin follows later.
**Code:** tokens in `globals.css` (ramps, type ladder, `.clay`,
`.shadow-card/.shadow-raised`, `.child-bg`), ramps generated by
`tools/design/ramps.py`. Material in `components/child/clay.tsx`; module
vocabulary in `components/child/kit.tsx` (MODULE, IconChip, ModuleCard,
SectionTitle) + PageHeader/BottomNav. Parent material in
`components/parent/flat.tsx`. Icons: `components/icons.tsx`.

## 1. Principles

1. **Colour is information *and* delight.** Each learning module owns ONE hue,
   used large and saturated — as a chunky tile fill, an icon chip, an accent
   bar, a progress fill. A child navigates by colour before reading. A strong
   gradient per screen (hero / CTA / section header) is welcome, not noise.
2. **Warm cream ground, warm ink.** Backgrounds are `--color-warm-white`
   (`#FEFAF5`) and `--color-surface-subtle` (`#F5EFE6`); text is
   `--color-text-primary` (`#3D3028`) and `--color-text-secondary` (`#6B5D50`,
   AA on white). No cold `slate-*` on child screens. Saturation is welcome in
   large areas — it does not have to be quarantined into chips.
3. **Dark ink on bright fills — never white on saffron.** See §3. This is the
   rule that keeps the palette bright while still clearing WCAG AA.
4. **The app decides; the child confirms.** Every screen leads with one obvious
   next action (home: «بازی کن»). One raised element per screen
   (`shadow-raised`); everything else rests at `shadow-card`.
5. **Windowed rows, never truncated lists.** Continue + next ~10 + a random
   tile + a door to the full page. Row arrows are always visible, never
   `hidden sm:flex` (WCAG 2.2 SC 2.5.7).
6. **Age bands change density, not inventory.** 3–5 / 6–7 / 8–10 (NN/g bands).
   3–5 get one big tile per row and no stats — they do **not** get fewer rooms.
7. **Friendly states in the copy, not the glyph.** A locked tile uses the same
   lock icon as every other locked thing; the warmth is the words
   («هنوز خوابه!»).
8. **Emoji carry identity and celebration on child screens.** Colourful emoji
   are how a pre-reader recognises a section and reads feedback:
   📚 ✏️ 🎵 📖 🔄 🎤 ✍️ 🔢 🃏 🏆 · ✅ ⭐ 🌟 🎉 ✨ 🔊. Lucide line icons
   (`components/icons.tsx`) are for **small utility controls**
   (back / close / settings / menu / media) and the **parent app**. An emoji is
   a font, not a token — it renders per-OS, takes no colour/stroke/size from the
   scale, and forces a bidi switch inside an RTL run — so it never does the job
   of a utility affordance, and never appears in the parent app's chrome.
   *Content* emoji (apples a child counts, board tokens, badge faces) are
   subject matter for `pixel-wizards-charachters`.
9. **Identity/BottomNav/feedback/celebration emoji render through `<Emoji>`,
   not a raw character.** `apps/web/src/components/shared/Emoji.tsx` serves
   Fluent Emoji ("Color" style, one glyph fell back to "Flat" over the 15KB
   budget) as static SVG from `apps/web/public/emoji/<name>.svg` — an `<img>`
   with explicit width/height, decorative by default (`alt=""` +
   `aria-hidden`) unless a Persian `alt` is passed for a glyph that is the
   only content, and a native-character fallback if the SVG fails to load.
   Content emoji and confetti/reaction bursts (`MarpeleBoard`'s particle set,
   `marpele-online`'s reaction picker) stay native — swapping a many-particle
   effect to `<img>` per particle would be the wrong trade. apps/mobile stays
   native for now too. License: `public/emoji/LICENSE` (MIT).

## 2. Type ladder

Child headings use a **rounded display face**, Baloo Bhaijaan 2 (verified full
Persian codepoint coverage + shaping), loaded via `next/font` as
`--font-baloo`; `--font-display` is a `var()` alias so the `font-display`
utility resolves through the cascade. **Headings only** — body text and any
glyph a screen is actively teaching stay Vazirmatn (`--font-persian`).

Seven steps, declared in `globals.css` `@theme inline` (Tailwind v4 generates
`text-<name>` utilities):

| token | size / line-height | use |
| --- | --- | --- |
| `text-display` | 2.5rem / 1.4 | the one big screen title (home hero) |
| `text-h1` | 2rem / 1.45 | celebration headings («آفرین! 🌟») |
| `text-h2` | 1.5rem / 1.5 | screen / section headings |
| `text-card-title` | 1.25rem / 1.5 | tile + card titles (`SectionTitle`) |
| `text-body` | 1.125rem / 1.8 | reading text — 1.8 for harakat legibility |
| `text-small` | 0.9375rem / 1.6 | captions. **15px is the child-screen floor** |
| `text-letter` | clamp(4.5rem, 4rem + 12vw, 7.5rem) / 1 | the glyph being taught |

## 3. Colour tokens

**Canvas** `.child-bg` cream gradient · **Surface** `--color-warm-white` ·
**Ink** `--color-text-primary` `#3D3028` / `--color-text-secondary` `#6B5D50`
(AA on white) · **Border** `--color-border` `#E8DDD0`.

**Brand — saffron.** `--color-brand-from #FBBF24` (amber-400) →
`--color-brand-to #F97316` (orange-500). The `bg-brand-gradient` /
`bg-brand-gradient-br` utilities set this fill **and** set
`color: var(--color-on-brand)`.

**`--color-on-brand: #451A03`** (Tailwind amber-950) — the ink for *all* text
and icons on any saffron surface (the gradient, the brand `bright` stop, hero
cards, primary CTAs, the parent XP banner). Generates the `text-on-brand`
utility. Measured against both gradient ends:

| surface | ratio | verdict |
| --- | --- | --- |
| on `#FBBF24` (amber-400, `brand-from`) | **8.97:1** | AA + AAA normal text |
| on `#F97316` (orange-500, `brand-to`) | **5.34:1** | AA normal text |

The rule: keep the gradient bright, never put white on saffron, and if a
surface ever fails, darken **this token** — never the gradient.

**Module hues — eleven 4-stop ramps** (ten modules + `brand`), generated by
`tools/design/ramps.py` into `--ramp-<name>-<stop>` in `globals.css` and
aliased in `@theme inline` as `--color-<name>-<stop>`. Regenerate the script;
never hand-edit a stop.

| stop | job | guarantee |
| --- | --- | --- |
| `bright` | the joyful Tailwind **-400** fill — **dark `ink` text sits here** | anchored straight on -400 |
| `soft` | pale Tailwind **-50** tint (chip bg, tile image area) — dark `ink` sits here too | anchored straight on -50 |
| `ink` | dark label / icon / title colour used **on** `bright` and `soft` | ≥ 5.0:1 vs `bright` (clears `soft` with room) |
| `deep` | 3D bottom edge, borders, text on `soft`, **the only stop white text may sit on** | ≥ 7:1 vs white, always darker than `bright` |

A single-stop hue has a *dead zone* — a mid-tone where neither white nor dark
text clears 4.5:1, which is exactly where the eye wants a cheerful fill. The
2026-09 audit found white tile titles there at ~1.9–2.5:1. The earlier pass
"fixed" it by darkening every `bright` toward -700 so white text would pass —
which drained the palette. The ramp does it the other way: `bright`/`soft` stay
anchored on the joyful -400/-50, and the two dark support stops (`ink`, `deep`)
are solved with headroom over the 4.5 floor, since the warm `.child-bg` ground
and sub-pixel AA eat into a solved-to-4.50 margin. The script also checks each
stop against the darkest end of the `.child-bg` gradient, not just pure white.

Hues (unchanged from the original brand): lessons = emerald · letters = Persian
blue · phonics = burnt orange · stories = teal · review = violet ·
speak = pomegranate · write = cyan · math = indigo · games = purple ·
rewards = gold · brand = saffron.

**Ad-hoc clay tones** — `clay.tsx` also exports a `Tone` union
(`emerald | sky | amber | rose | violet | orange | teal | fuchsia | lime`) with
a `TONES` record (all `[fill, edge, ink]` AA-checked ≥ 6:1) and
`toneVars(tone)`, for the handful of places that need per-item colour outside
the module ramps — the three phonics vowel-mark tiles, the maths rooms, the
مارپله board pastels. Same dark-ink-on-bright contract as the ramps.

**Radius** 12 (inputs) / 16 (cards) / 24 (featured) / full (chips-pills).
**Shadows** exactly two: `shadow-card`, `shadow-raised`.
**Touch** ≥ 48dp all, ≥ 56dp primary, ≥ 64dp band-1; gaps ≥ 12.
**Motion** one spring (400/17 tap, 300/20 enter); durations 200–400ms (band 1 up
to 600); celebration ≤ 1.5s; `prefers-reduced-motion` → fades.

**`scripts/check-child-design-tokens.sh`** (`npm run lint:design`) is
**advisory** — it always exits 0. It flags raw `rounded-md/lg/[…]` and
`shadow-sm/md/lg` reappearing, but it must never block gradients, colour or
saturation. It is a nudge, not a gate.

## 4. Two registers

The child app and the parent app are deliberately different materials. They
share the icon set, the type scale, the ramps and the warm neutral family —
the *system* is one; only the material differs. A parent checking progress at
11pm and a five-year-old choosing a story are different users.

- **Child = clay.** Thick, coloured, pressable: a `bright` fill over a solid
  `deep` edge, an inset top highlight, a soft ambient shadow, ~4px of travel on
  press. The travel matches the edge thickness the surface loses, so the bottom
  stays planted and only the top face moves. `.clay` (globals.css) is the
  recipe; it takes its colours from `--clay-fill` / `--clay-edge` (and radius
  from `--clay-radius`, because an unlayered rule beats Tailwind's layered
  utilities) so one rule serves all eleven ramps and no component hard-codes a
  hex. `clayVars(ramp)` and `toneVars(tone)` feed it.

- **Parent = flat, but warm.** Soft rounded cards (`rounded-2xl`) on a cream
  ground (`--color-parent-bg #F7F1E8`), white surfaces
  (`--color-parent-surface`), one gentle shadow level (`shadow-card`), warm
  borders (`--color-border`), saffron and ramp accents — **never** cold slate.
  Warm ink: `--color-parent-text #33291F`, `--color-parent-muted #6B5D50`
  (both AA on white and on the cream). Calmer than the child side — no clay, no
  bounce, unhurried motion (eased, not sprung) — but the same family.
  `components/parent/flat.tsx` is the kit:
  - **`Panel`** — the only container. No raised variant ("one raised element"
    is a child rule for steering a pre-reader).
  - **`Stat`** — a pastel card in a ramp's `soft` with the ramp's `ink` and an
    **emoji** (📖 ✅ 🔥 …), `tabular-nums` on the value. The illustrated stat
    card, not a bare tinted box. Falls back to a ramp-tinted `<Icon>` when no
    emoji is passed.
  - **`FlatBar`** — progress: thinner than `ClayBar`, eased not sprung, `label`
    required.
  - **`PageHeader`** — the back bar. One component so the affordance is in the
    same place at the same size everywhere; chevron is the icon set's `back` /
    `forward`, so it can never point the wrong way in RTL.
  - **`Group` / `NavRow`** — a labelled row list whose label is a real `<h2>`
    tied to the list (`aria-labelledby`). `Group` is a bordered, divided
    container (`rounded-2xl` + warm border + `shadow-card`) rather than a stack
    of separately-floating cards — several settings rows carry their own
    padding and dividers, and re-laying them out as free cards would double the
    chrome. `NavRow` renders a `<Link>` for `href`, a `<button>` for `onClick`,
    and shows its `icon` in a **soft saffron chip** on the leading side — a warm
    marker, not a bare grey stroke. `px-5 py-4`, `min-h-[56px]`.
  - **`.btn-brand`** (globals.css) — the parent app's one filled action. Uses
    `--ramp-brand-deep` with white text (7:1) because `bg-amber-500/-600` with
    white measure 2.5:1 / 3.2:1.

  **`ParentGate.tsx` is a deliberate exception** — the PIN-pad security gate
  keeps its dark `bg-slate-900` sheet. It is a lock screen, not a parent
  surface, and reads as a different context on purpose.

  The dashboard **XP / level banner** rides the saffron `bg-brand-gradient-br`
  with `text-on-brand` dark ink (same 8.97:1 / 5.34:1 as §3) — the earlier
  white-on-violet-500→purple-600 banner failed AA. The progress track is
  `rgb(69 26 3 / 0.18)` and the fill is `var(--color-on-brand)`, so the whole
  banner stays one hue.

## 5. Components

**Child material** (`components/child/clay.tsx`) — knows nothing about modules:

- **ClayButton** — the one pressable thing. Renders a link with `href`, a
  button otherwise. Sizes are floors (40/48/56), all above the 44px WCAG 2.5.8
  minimum.
- **ClayTile / ClayMiniTile** — row tile / square carousel tile, each with a
  `locked` state that keeps its shape so the grid doesn't reflow, and a `glyph`
  escape hatch for the one case where the mark *is* the content being taught
  (the Persian digit ۴, the counted apple). `ClayTile` takes an optional
  `tone`.
- **ClayBar** — progress. `label` required; the fill animates from its previous
  value, because the movement is the reward.
- **ClayChip / ClayIconChip** — `soft` ground with `ink` text, a pairing the
  ramps already solve for AA.
- **Tone / TONES / toneVars / clayVars** — the colour plumbing (§3).

**Child vocabulary** (`components/child/kit.tsx`) — which hue and glyph mean
what: `MODULE`, plus `IconChip` / `ModuleCard` / `ModuleBar` / `ModuleChip` /
`SectionTitle` bound to a `ModuleKey`. Every `ModuleKey` is also a ramp name,
enforced at the type level — adding a module without its ramp is a build error.

- **Icon** (`components/icons.tsx`) — the only way to draw a line icon. Lucide,
  one 24px grid, sizes tied to the type scale. `aria-hidden` by default; pass
  `label` for a named `img`.
- **IconChip** — module icon on soft tint. The glyph inherits the module tint
  via `currentColor`; nav icons thicken on active (stroke 2 → 2.4).
- **ModuleCard** — chunky clay row tile in the module hue (icon + title + sub),
  ≥ 76px. Takes an optional `tone` for the per-item-colour cases.
- **SectionTitle** — `font-display` `text-card-title` heading + module colour
  tick.
- **PageHeader** — sticky, 48px back target, title + module accent bar off the
  same ramp the screen body uses. A per-screen hero / CTA / section-header
  gradient is welcome in the body; the header bar itself stays quiet.
- **BottomNav** — active tab = soft saffron pill (`layoutId` spring), ≥ 52px,
  five-item ceiling (four tabs + `ParentDoorNav`). «جوایز» holds the fifth slot.
- **StoryFallback** (`child/story/page.tsx`) — when a story has no `cover_url`,
  a per-story id-keyed hue + a muted `SceneBackdrop` + a glyph, so a story's
  colour is stable (keyed to its id, not its list position).

**مارپله** — one copy of each board object in
`components/child/MarpeleBoard.tsx`, all on the games ramp: `TurnChip`,
`RollRow` (the roll button is `ClayButton`, so "not your turn" is the
material's own disabled state), `ChallengeModal`, `GameOverScreen`. The board
grid is bespoke — it is a board, not a list — and its plain squares are dealt
**six pastels by `n % 6`** (`TILE_PASTELS` in that file): a مارپله board is a
wall of colour, and that IS the toy. `start` / `finish` / `ladder` / `snake`
then override with four semantic colours (module / rewards ramps, and a
green / red pair).

**Every interactive component defines:** rest / pressed (spring scale ~0.96) /
active (pill or ring) / disabled (opacity-40, never hidden) / focus-visible.

## 6. Status

**Child app** — all screens on the system: home, lesson, story, story-reader,
review, speak, write, math, phonics, games (memory + مارپله), rewards. The
`design-recovery` pass (Phases 0–4b) restored per-item colour, per-screen
gradients, chunky `ModuleCard` tiles, the مارپله pastels and the colourful
emoji that the 2026-09 "visual UX pass" had flattened. Story reader and lesson
screens got a **light touch only** — contrast fix + type ladder, no redesign.
One-hue-per-module, windowed rows, every-room-visible-on-home, the read-aloud
feature and all a11y / RTL fixes from the earlier pass still hold.

**Parent app** — all eight screens on `components/parent/flat.tsx`, warmed up
in Phase 5 (cream ground, rounded cards, one shadow, saffron accents, emoji
stat cards, XP banner on `text-on-brand`). The dashboard sets the shape: a
sentence built from data that can support the claim
(`lib/parentHeadline.ts`), then three numbers, then one action; everything else
demoted under «جزئیات». `ParentGate.tsx` stays a distinct dark lock screen.

**Read-aloud** — the child records at the end of a story
(`components/child/ReadAloud.tsx`, clay); the parent listens at
`/parent/recordings` (flat). Delivery to a grandparent is not built — see
`docs/read-aloud.md` for that and the consent / retention model.

**Admin** — has a real, partially-adopted kit
(`apps/admin/src/components/ui.tsx`); needs a migration-completion pass, not a
new system. Not started.

**Rule for new screens:** no new colours, no new radii, no new shadows —
compose the kit. New joy comes from *using* the ramps and emoji boldly, not
from inventing tokens.
